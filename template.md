ТЕМА: Ownership и Borrowing в Rust
ДАТА: 2026-02-03

ИСТОЧНИКИ:
- The Rust Programming Language, ch.4
- Rustlings

ЗАЧЕМ:
- Избегать use-after-free
- Гарантировать thread-safety на этапе компиляции
- Уменьшить runtime overhead (нет GC)

ИДЕЯ:
В Rust у каждого значения есть владелец.
Когда владелец выходит из области видимости — память освобождается.

Заимствование позволяет временно использовать значение без передачи владения.

ПРИМЕР:
```rust
fn main() {
    let s = String::from("hello");
    takes(s);
    // s недоступна
}
```
ОШИБКА:
Попытка иметь две mutable ссылки одновременно

ПОЧЕМУ ПЛОХО:
Может привести к data race

КАК RUST ЛОВИТ:
На этапе компиляции

В ПРОДАКШЕНЕ:
- Безопасная конкурентность
- Zero-cost abstractions
- Высоконагруженные сервисы

АНАЛОГИЯ:
Ownership — это договор аренды квартиры.
Mutable borrow — ты внутри один.
Immutable borrow — гости, но никто не двигает мебель.
